# 舞台提示执行台

本地单人使用的舞台提示（cue）执行台：开场前录入 2～12 条按顺序排列的提示，演出中逐条确认发出；演出中可随时改写或重排尚未发出的提示，已发记录保持原样。已结束或提前收场的演出可**归档本场**，保存为独立档案，下一场开始后仍可随时回看。

技术栈：Python / FastAPI + SQLite + 原生 HTML/CSS/JavaScript（无前端构建步骤）。

## 启动（一条命令）

```bash
docker compose up --build
```

- 访问地址：**http://localhost:8000**
- 端口：**8000**
- 停止：`Ctrl + C`
- 数据保存在 Docker 卷 `cue-data` 中，刷新页面、重启容器/服务都不会丢失提示顺序与进度。

## 本地运行（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

同样访问 http://localhost:8000 。数据库文件默认在 `app/data/cues.db`，可用环境变量 `DB_PATH` 覆盖。

## 使用流程

1. **开场前设置**：录入 2～12 条提示，每条需唯一编号 + 非空内容，顺序即发出顺序；点击「开始演出」。
2. **演出中**：页面突出显示**当前待发**提示与**下一条**，右侧为**已发记录**。
   - 「确认发出」：服务端把**那一刻**的内容记入已发并推进一条；全部发出后显示完成横幅。
   - 「暂停发出 ⏸」：演出中可随时暂停（如处理突发情况），处理完后点「恢复发出 ▶」继续。暂停**不清空提示、不推进进度**；暂停期间页面显示暂停标记、确认按钮禁用（接口同样拒绝），**改写、重排、归档仍可用**，恢复后按暂停期间改过的最新顺序和内容继续。暂停标记保存在数据库中，刷新页面或重启服务后仍保留。
   - 待发列表中可**改写**（编号/内容）或用 ↑↓ **重排**任何尚未发出的提示；已发记录不可更改。
3. 「重新开始」清空进度，回到设置页。
4. **归档本场**：演出中（提前收场）或全部发出（已结束）时，点击演出页的「归档本场」，输入非空的**场次名称**后保存：
   - 档案记录归档时间、当时状态（已完成 / 提前收场）、**按发出顺序**排列的已发编号、内容快照与发出时间，以及**按待发顺序**排列的剩余编号和内容；
   - 保存档案与清空当前提示在**同一事务**内完成：保存失败不会清空当前提示；成功后回到开场前设置、版本号 +1，可立即录入下一场；
   - 开场前（设置页）不能归档；**同版本的归档与确认/编辑等操作只有一个生效**，重复提交因版本过期返回 `409`，不会多建档案。
5. **回看档案**：点击右上角「📚 档案库」查看列表（含名称、归档时间、状态，按归档时间倒序、同时间按档案 ID 倒序），点击任意一条查看已发快照与剩余未发详情。后续录入、重置和重启服务都不会改变已有档案。
6. **以此开新场**：在**档案详情**中点击「以此开新场 ▶」并确认，即可以档案为底稿直接开始下一场：
   - 先取档案中**按发出顺序**排列的已发编号与**内容快照**（页面所见版本，不含发出时间），再接上**按待发顺序**排列的剩余编号与内容，全部作为新场的**待发提示**，顺序即新场发出顺序；
   - 成功后直接进入**演出中**：已发为空、当前指向第一条、版本号 +1；不继承旧场的发出时间或进度，**原档案不做任何修改**；刷新页面或重启服务后新场状态仍保留；
   - 仍需满足 2～12 条、编号唯一、内容非空的规则（正常归档得到的档案天然满足）；**仅开场前（设置页）允许生效**，演出中/已完成时按钮禁用。
7. **场次对照**：在档案库列表点击「场次对照 ⇄」，分别选择**基准场次**与**对照场次**，即可并排查看两场提示的发出节奏差异：
   - 按**编号精确匹配**取两场提示的并集，按编号字符串升序列出；每条显示两侧的**内容快照**、**已发 / 未发 / 缺失**状态，以及**相对发出秒数**（各场以首条已发提示的发出时间为零点，保留毫秒，暂停时长计入；未发、缺失或整场无已发记录时显示 `—`）；
   - 仅当两侧**均已发出且内容完全一致**时，计算「对照 − 基准」的秒数差（**正值表示对照场更晚**），其余情况显示 `—` 及原因；没有可对照的编号时页面会给出提示；
   - 切换任一场次会立即清空旧结果并重新查询，较慢的旧响应不会覆盖新结果；对照是**只读查询**，不修改档案、当前演出或版本号，任意演出状态下都可使用。

## 并发与一致性规则

- 页面上的每次确认 / 编辑 / 重排 / 归档都携带页面当前看到的**版本号**。
- 服务端每次成功变更都会把版本号 +1；携带过期版本号的请求返回 `409` 并附带最新状态，页面随即刷新显示。
- 因此：**同一版本的两个操作只有一个生效**；**重复点击不会跳过提示**（按钮在请求在途时禁用，且第二次点击的版本号已过期）；**编辑胜出后，基于旧内容的确认会被拒绝**；**重复提交归档不会多建档案**。
- 确认发出的内容以服务端当时存储的内容为准并快照保存，已发记录此后不受编辑/重排影响。
- 暂停/恢复同样携带页面版本号：**仅演出中**且目标状态与当前不同时生效，「暂停标记 + 版本号 +1」在同一事务内落库，写入失败两者都不变；**非演出中、目标已达成（如已暂停时再暂停）或版本过期都返回 `409` 及最新状态**。因此**同一版本的暂停、恢复、确认和编辑最多一个生效**。
- 暂停期间「确认发出」即使用最新版本号也返回 `409` 及最新状态；编辑、重排、归档不受影响。归档、重置、录入新场、以档案开新场**成功后一律回到未暂停**；这些操作失败时保留原状态，既有档案不变。旧版本数据库启动时自动补上暂停标记列，默认未暂停。
- 归档的「写档案 + 清空提示 + 版本 +1」在同一数据库事务内提交，任一步失败整体回滚，不会出现档案没存上、提示却被清空的情况。
- 「以此开新场」同样携带页面版本号并在锁内检查：**非开场前或版本过期返回 409**（附最新状态），同版本的重复点击或并发提交最多一次生效；「写入新场提示 + 进入演出中 + 版本 +1」在同一事务内提交，失败时当前场次与档案都不变。
- 档案独立于当前场次存储：录入新场次、重新开始（重置）、以档案开新场、重启容器/服务都不会修改或删除档案；旧版本数据库启动时会自动创建档案表，可直接使用。
- 场次对照（`GET /api/compare`）是纯查询：不携带版本号、不加写锁，不修改档案、当前演出或版本号，开场前 / 演出中 / 已完成任意状态都可随时调用。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 获取当前状态（版本号、暂停标记、当前/下一条、待发与已发列表） |
| POST | `/api/setup` | `{cues:[{number,content}]}` 录入 2～12 条并开始演出 |
| POST | `/api/confirm` | `{version}` 确认发出当前提示（暂停期间即使版本最新也返回 409） |
| POST | `/api/pause` | `{version, paused}` 暂停/恢复发出（仅演出中且目标与当前不同才生效，否则 409） |
| POST | `/api/edit` | `{version, cue_id, content, number?}` 改写未发提示 |
| POST | `/api/reorder` | `{version, order:[cue_id…]}` 重排全部未发提示 |
| POST | `/api/archive` | `{version, name}` 归档本场（演出中/已完成），保存档案并清空回到开场前 |
| GET | `/api/archives` | 档案列表（名称、归档时间、状态；按归档时间/ID 倒序） |
| GET | `/api/archives/{id}` | 档案详情（已发快照、剩余未发） |
| GET | `/api/compare?base={id}&compare={id}` | 对照两场档案的发出节奏（只读）；档案不存在 404 |
| POST | `/api/archives/{id}/start` | `{version}` 以此档案开新场（仅开场前）；档案不存在 404、校验失败 400、非开场前/版本过期 409 |
| POST | `/api/reset` | 清空进度，回到设置（不影响档案） |

## 暂停 / 恢复发出（请求示例）

演出页右上角可见当前页面版本号（`vN`），暂停与恢复都提交**目标状态** `paused` 与该版本号：

```bash
# 暂停发出
curl -X POST http://localhost:8000/api/pause \
  -H 'Content-Type: application/json' \
  -d '{"version": 5, "paused": true}'

# 恢复发出
curl -X POST http://localhost:8000/api/pause \
  -H 'Content-Type: application/json' \
  -d '{"version": 6, "paused": false}'
```

成功（`200`）返回最新状态：`paused` 已切换为目标值、`version` 在原版本上 +1，`status` 取值不变（仍为 `live`）：

```json
{
  "version": 6,
  "status": "live",
  "paused": true,
  "current": { "id": 2, "number": "A1", "content": "灯光渐亮" },
  "remaining": 3
}
```

错误情况（均返回 `409 {"error": "conflict", "message": "操作已过期", "state": {...}}`，`state` 为最新状态）：

- 当前不是演出中（开场前 / 已完成）；
- 目标已达成（已暂停时再暂停、未暂停时再恢复）；
- 版本号已过期（同版本已有暂停/恢复/确认/编辑先生效）。

暂停期间 `POST /api/confirm` 即使用最新版本号也返回 `409` 及最新状态；`/api/edit`、`/api/reorder`、`/api/archive` 不受影响。

## 以档案开新场（请求示例）

先在档案详情页看到目标档案 ID 与当前页面版本号（右上角 `vN`），然后：

```bash
# version 为页面所见版本号；id 为档案 ID
curl -X POST http://localhost:8000/api/archives/3/start \
  -H 'Content-Type: application/json' \
  -d '{"version": 7}'
```

成功（`200`）返回新场的完整状态：`status` 为 `live`、`issued` 为空、`current` 指向第一条（档案已发顺序首条；若档案没有已发则为剩余未发首条）、`version` 在原版本上 +1，提示内容即页面所见的快照版本。

```json
{
  "version": 8,
  "status": "live",
  "paused": false,
  "current": { "id": 4, "number": "A1", "content": "灯光渐亮" },
  "next": { "id": 5, "number": "A2", "content": "音乐起" },
  "pending": [
    { "id": 4, "number": "A1", "content": "灯光渐亮" },
    { "id": 5, "number": "A2", "content": "音乐起" }
  ],
  "issued": [],
  "total": 2,
  "remaining": 2
}
```

错误情况：

- `404 {"error": "archive_not_found"}`：档案不存在；
- `400`：拼出的提示不满足 2～12 条 / 编号唯一 / 内容非空（`error` 为中文原因）；
- `409 {"error": "conflict", "message": "操作已过期", "state": {...}}`：当前不是开场前，或版本号已过期；响应体中的 `state` 为最新状态。

## 场次对照（请求示例）

对照接口接收两个档案 ID（`base` 为基准场次、`compare` 为对照场次），是只读查询，无需版本号，任意演出状态可用：

```bash
curl 'http://localhost:8000/api/compare?base=1&compare=2'
```

成功（`200`）返回两场摘要与按编号字符串升序的并集明细：

```json
{
  "base":    { "id": 1, "name": "10 月 1 日晚场", "status": "done", "issued_count": 2, "pending_count": 1 },
  "compare": { "id": 2, "name": "10 月 2 日晚场", "status": "live", "issued_count": 2, "pending_count": 1 },
  "rows": [
    {
      "number": "A1",
      "base":    { "status": "issued",  "content": "灯光渐亮", "offset_seconds": 0.0 },
      "compare": { "status": "issued",  "content": "灯光渐亮", "offset_seconds": 0.0 },
      "delta_seconds": 0.0,
      "delta_reason": null
    },
    {
      "number": "A2",
      "base":    { "status": "issued",  "content": "音乐起", "offset_seconds": 12.5 },
      "compare": { "status": "issued",  "content": "音乐起", "offset_seconds": 15.25 },
      "delta_seconds": 2.75,
      "delta_reason": null
    },
    {
      "number": "A3",
      "base":    { "status": "pending", "content": "幕落", "offset_seconds": null },
      "compare": { "status": "missing", "content": null,   "offset_seconds": null },
      "delta_seconds": null,
      "delta_reason": "基准场未发出；对照场无此编号"
    }
  ]
}
```

字段说明：

- `rows[].base` / `rows[].compare`：该编号在基准场 / 对照场的一侧视图。`status` 为 `issued`（已发）/ `pending`（未发）/ `missing`（该场无此编号）；`content` 为内容快照（已发给出发出时的快照，缺失为 `null`）。
- `offset_seconds`：相对**本侧场次首条已发提示**发出时间的秒数（使用档案保存的发出时间，保留小数秒，暂停时长计入）；未发、缺失或整场无已发记录时为 `null`。
- `delta_seconds`：「对照 − 基准」的秒数差，**正值表示对照场更晚**；仅当两侧均已发出且内容完全相同时给出，其余为 `null` 并由 `delta_reason` 给出中文原因（未发出 / 无此编号 / 内容不一致等）。

错误情况：`404 {"error": "archive_not_found"}`——任一档案不存在。
